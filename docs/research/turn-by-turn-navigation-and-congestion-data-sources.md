# "현재 구간" 실시간 도보 내비게이션 화면 — 턴바이턴 안내 API / 혼잡도 데이터 조사

조사일: 2026-09-14
조사 목적: 디자인 목업(`디자인/지도(현재구간).png`)의 "현재 구간" 실시간 도보 내비게이션 화면(다음 안내 텍스트,
남은 시간/거리, 혼잡도, 날씨)을 만들기 전에 — ① 턴바이턴(구간별 안내 문구) 도보 경로 API가 실제로
존재하는지, ② 도보 구간/장소 단위 실시간 혼잡도 데이터를 정직하게 채울 방법이 있는지 확인.

**결론 1 (턴바이턴 도보 경로): 있다 — 단 Tmap(SK Open API) 보행자 경로안내 API뿐이다.**
네이버 클라우드플랫폼(NCP)은 도보 옵션 자체가 없고(실측 400 에러), 카카오모빌리티 도보 길찾기는
좌표(폴리라인)만 주고 안내문구 필드가 아예 없다. Tmap의 `보행자 경로안내` API만 "리본 에서 좌회전 후
37m 이동" 같은 사람이 읽는 안내문구(`description`)와 회전코드(`turnType`)를 실제로 준다.

**결론 2 (실시간 도보/장소 혼잡도): 대구에서 정직하게 채울 방법이 없다.**
네이버·카카오 공식 API 어디에도 혼잡도 필드가 없다(소비자 앱 UI 전용 기능). 관광지 실시간 혼잡도는
KT가 해양수산부 "해수욕장 혼잡도 신호등"에, 서울시가 "서울 실시간 도시데이터"에 각각 통신사 데이터를
공급하는 사례가 실재하지만 전부 지자체·기관 단위 개별 계약이고 대구에는 동급 서비스가 없다.
SKT 지오비전 "장소 혼잡도"는 상품 자체는 있으나 요금·자격이 비공개(문의 필요)라 학생 프로젝트가 지금
당장 쓸 수 있는지 불명확하다. 기존 `ParkingCongestionBadge`는 "장소 근처 주차장 잔여율"이라는 별개
프록시이고 도보 구간의 사람 밀집도와는 무관해 이 화면에 그대로 재사용하면 안 된다.

## 1. 턴바이턴 도보 경로 안내 — 실측 근거

### 1-1. NCP(네이버 클라우드플랫폼) — 도보 옵션 자체가 없음 (실측)

`src/lib/services/naverDirections.ts`가 쓰는 `map-direction-15`(자동차 전용, Direction 5/15 둘 다
자동차 상품) 엔드포인트에 프로젝트의 실제 `.env.local` 키로 `option=walking`을 직접 넣어 호출:

```
GET https://maps.apigw.ntruss.com/map-direction-15/v1/driving?start=...&goal=...&option=walking
→ 400 { "error": { "errorCode": 400, "code": 1, "message": "'option(walking)' is wrong, walking is unknown" } }
```

NCP Maps 공식 상품 목록(`ncloud.com/product/applicationService/maps`)에도 Directions 계열은
자동차 길찾기(Direction 5/15)만 있고 보행자 상품이 없다. **NCP에는 보행자 경로안내 자체가 없다** —
옵션 이름을 바꿔서 될 문제가 아니라 상품이 없는 것으로 확정.

### 1-2. 카카오모빌리티 — 도보 API는 있지만 안내문구가 없다

공식 문서(`developers.kakaomobility.com/affiliate/walking/directions`, verbatim 확인):

> "해당 API는 제휴 파트너 전용 API입니다. 사용을 위해서는 사전 제휴 계약이 필요합니다"

응답 스키마 전문(문서 verbatim):
- `trans_id`, `routes[].result_code/result_message`
- `summary`: `distance`(m), `duration`(초)
- `sections[].roads[]`: `distance`, `duration`, `vertexes`(좌표 배열)

**"guide" 필드가 없다** — 음성/텍스트 안내문구, 회전 지시 필드가 응답 어디에도 없다. 즉 카카오 도보
API는 폴리라인 + 총 거리/시간만 주고, "200m 직진 후 우회전" 같은 구간별 안내는 애초에 만들 수 없다.

문서상 "제휴 파트너 전용"이지만, 실제 데브톡 사례(`devtalk.kakao.com/t/directions-api/151624`,
학생 프로젝트, 비상업 학습 목적 명시)는 신청 후 승인됐다 — 승인 문턱이 문서보다는 낮을 수 있음
(단, 이 조사에서 승인 조건까지 확정 검증은 못 함). 인증은 `Authorization: KakaoAK ${REST_API_KEY}`.

### 1-3. Tmap(SK Open API) — 실제로 안내문구를 준다 (문서 verbatim 확인)

- 엔드포인트: `POST https://apis.openapi.sk.com/tmap/routes/pedestrian` (헤더 `appKey`, `version=1` 필수)
- 응답은 GeoJSON `FeatureCollection`. `Point` 피처(경유/시작/도착 지점)의 `properties`에:
  - `description`: **"리본 에서 좌회전 후 37m 이동"** 같은 사람이 읽는 한국어 안내문구
  - `turnType`: 회전코드(예 12=좌회전, 13=우회전, 200=출발, 201=도착, 211=횡단보도)
  - 첫 Point에만 `totalDistance`, `totalTime`
  - `LineString` 피처: 구간별 `distance`(m), `time`(초), `coordinates`
- 목업이 요구하는 "200m 직진 후 우측 보행로로 이동" 형태와 정확히 같은 종류의 데이터다.

**요금/자격은 이번 조사에서 완전히 확정하지 못함(미검증)**: T맵 API 공식 요금 안내 페이지는
"경로탐색 일 1천 건 무료, 초과 시 종량제/월정액"이라고 명시하지만(기존
`docs/research/tmap-data-api-and-nationwide-parking.md`에서 이미 확인), 이 무료 한도가
`/routes/pedestrian`(보행자)까지 포함하는지 별도 상품 카탈로그(`openapi.sk.com/products/detail?linkMenuSeq=46`,
동적 렌더링이라 WebFetch로 본문을 못 읽음)로는 확정하지 못했다. 커뮤니티 글타래(`community.openapi.sk.com`,
도메인 자체가 DNS 조회 실패해 접속 불가)에서 검색 스니펫으로만 "건당 10원, 일 1,000건 무료"라는
언급을 봤으나 1차 출처 페이지를 직접 열람하지 못해 **참고용으로만** 남긴다. 실제 신청 전 반드시
`openapi.sk.com`에서 보행자 경로안내 상품 페이지의 요금/자격 조항을 다시 확인할 것.

### 1-4. ODsay — 도보 전용 turn-by-turn 없음

ODsay 대중교통 길찾기 API의 도보 구간은 "직선거리 기반 추정"이고, 자체 지도 서비스(ODsay Map)의
정밀 도보 엔진은 유료 내부 상품으로 API로 공개돼 있지 않다(검색 스니펫 기준, 1차 문서 미확인).
도보 전용 턴바이턴 상품이 아니라서 이번 조사 목적에는 후보에서 제외.

## 2. 실시간 혼잡도 — 실측 근거

### 2-1. 기존 코드가 이미 하고 있는 것 — 주차장 혼잡도 프록시 (재확인)

`src/components/screens/ResultsScreen.tsx`의 `ParkingCongestionBadge`(29~46행)는 주석에서부터
스스로 "관광지 자체의 실시간 방문자 혼잡도가 아니라(그런 데이터가 없음) 그 장소 근처 대구 주차장의
실시간 혼잡도"라고 명시하고 있다. `src/lib/parkingDisplay.ts`의 `occupancyLabel`은 대구
통합주차정보시스템(`pis.daegu.go.kr`)의 잔여면수/총면수 비율로 여유/보통/혼잡을 계산한다
(주차장 데이터, 대구 지역 한정, `src/lib/tools/parking.ts` 실측 이미 검증됨).

**이 프록시를 "현재 구간"(도보 이동 중) 화면에 그대로 갖다 쓰면 안 된다** — 걷고 있는 사람이 몰려서
붐빈다는 뜻이 아니라 "근처 주차장에 차 댈 자리가 없다"는 뜻이라, 화면 맥락(보행자 혼잡)과 완전히
다른 데이터를 같은 라벨("혼잡도")로 보여주게 되어 사용자를 오도한다.

### 2-2. 네이버·카카오 공식 API — 혼잡도 필드 없음

카카오 로컬 API 공식 문서(`developers.kakao.com/docs/ko/local/common`)의 장소 검색 응답 필드는
이름/카테고리/주소/좌표/전화/URL 수준이고 혼잡도류 필드가 없다. 데브톡 검색에서도 개발자가
"혼잡도 필드"를 문의한 사례 자체가 나오지 않는다 — 카카오맵 앱이 보여주는 "방문자 빅데이터 기반"
정보(연령/성별/요일별)는 앱 자체 기능이며 공개 API로 노출되지 않는 것으로 판단된다(카카오 측
공식 "지원 안 함" 문서를 직접 찾지는 못해 **부재 추정**임을 명시 — 완전한 반증은 어려움).

### 2-3. 통신사 유동인구/혼잡도 — 상품은 있으나 접근성 불명확 (SKT), 행정동 단위라 부적합 (LGU+)

- **SKT 지오비전**(`openapi.sk.com/products/detail?svcSeq=56`): "실시간 장소 혼잡도", "시간대별 장소
  혼잡도", "통계성 장소 혼잡도" 3종이 상품명으로 존재한다(페이지에서 확인). 하지만 가격표·신청
  자격·API 형태(실시간 REST 호출인지 배치 파일 판매인지)는 해당 페이지가 메뉴 구조만 노출하고
  본문은 동적 렌더링이라 WebFetch로 확인 불가 — **미검증**. 이메일 문의(`skopenapi@sktelecom.com`)
  없이는 학생 프로젝트가 쓸 수 있는 상품인지 판단할 근거가 부족하다.
- **LGU+ 7대광역시 시간대별 유동인구**(대구 포함, `data.edmgr.kr`): 검색 스니펫 기준
  "행정동 단위, 월별/요일별/시간대 구간(0~9/9~12/12~18/18~24시) 집계"다 — 좌표 단위 실시간이
  아니라 코스 한 구간(보행 5~15분)에 붙이기엔 해상도가 너무 낮고 실시간성도 없다.
- **대구 수성구 CCTV 유동인구**(`data.go.kr/data/15097213`): 검색 스니펫 기준 "월별/분기별" 집계이고
  수성구 한정, CCTV 지점 단위 — 마찬가지로 실시간·전역 커버리지가 아니다.

### 2-4. 관광지 혼잡도 신호등 — 실재하지만 대구엔 없음 (참고 사례)

- **KT × 해양수산부 "해수욕장 혼잡도 신호등"**: 실시간 데이터 공급 사례가 실재한다(검색 스니펫
  확인). 그러나 해수욕장 전용이고 대구는 해안 도시가 아니라 애초에 적용 대상이 아니다.
- **서울시 × KT "서울 실시간 도시데이터"**(`data.seoul.go.kr/SeoulRtd/`): **가장 강력한 참고
  사례** — 서울 시내 약 120개 주요 장소(예: 여의도공원)에 대해 5분 주기로 갱신되는 실시간 인구
  혼잡도(`AREA_CONGEST_LVL`, 여유/보통/약간붐빔/붐빔)를 무료 오픈 API로 제공한다(서울 열린데이터광장
  공식 소개 기사·서비스 페이지로 확인). 이건 "통신사 데이터 + 지자체 예산/협약이 있으면 장소 단위
  실시간 혼잡도가 실제로 가능하다"는 증거이자, 동시에 "그 협약이 없는 대구는 못 쓴다"는 반증이기도
  하다. **대구광역시 D-데이터허브(`data.daegu.go.kr`)를 검색한 결과 이와 동급의 실시간 인구
  혼잡도 서비스는 확인되지 않았다** — 카탈로그가 방대해(19,475개 데이터셋) 전수 확인은 못 했지만
  ("실시간 도시데이터", "혼잡도" 키워드로 걸리는 대구 전용 서비스가 없음), 서울의 SeoulRtd 같은
  대표 서비스가 있었다면 검색에 노출됐을 가능성이 높다.

## 권장사항

1. **턴바이턴 안내는 Tmap 보행자 경로안내 API로 새로 만든다.** 지금 프로젝트 키(NCP/Kakao)로는
   원천적으로 불가능하므로, SK Open API(`openapi.sk.com`) 신규 가입 + 앱키 발급이 선행 조건이다.
   가입 전 요금제(특히 무료 한도가 보행자 엔드포인트에도 적용되는지)를 상품 페이지에서 재확인할 것 —
   본 조사에서 미확정으로 남긴 부분이다.
2. **"혼잡도"는 이번 화면에 넣지 않는다(빈칸/미표시).** 대구를 실시간으로 정직하게 커버하는
   장소/보행 혼잡도 소스가 확인되지 않았다. 기존 `ParkingCongestionBadge`(주차장 잔여율)를 그대로
   재사용하는 것은 데이터의 의미가 달라 "혼잡도" 라벨을 붙이면 안 된다 — 굳이 넣고 싶다면 라벨을
   "근처 주차 여유"처럼 정직하게 바꾸고 도보 구간이 아니라 목적지 도착 후 주차 맥락에서만 노출해야
   한다.
3. **날씨는 이미 확보된 소스**(코스 화면의 상단 날씨 배지, `77bf228` 커밋에서 다룬 것과 동일 데이터)를
   재사용하면 된다 — 이번 조사 범위 밖이라 별도 검증은 하지 않았다.
4. SKT 지오비전 "장소 혼잡도"는 접근성이 불명확하니, 정말 필요해지면(예: 향후 서울/타 도시 확장)
   `skopenapi@sktelecom.com`에 학생 프로젝트 신분으로 직접 문의해 자격·요금을 1차로 확정하는 별도
   조사가 필요하다 — 지금 단계에서 이 화면 때문에 붙잡을 우선순위는 아니다.

## 조사 한계 (투명성 고지)

- Tmap 보행자 경로안내의 **정확한 무료 한도/요금**은 상품 상세 페이지·커뮤니티 도메인
  (`community.openapi.sk.com`, DNS 조회 실패)에 직접 접근하지 못해 확정하지 못했다. 실제
  신청 전 재확인 필요.
- 카카오모빌리티 도보 API의 **실제 승인 조건**(제휴 계약이 문서상 요건인데 학생 사례는 승인된 것으로
  보이는 간극)은 데브톡 글타래 하나로만 판단했다 — 표본이 작다.
- SKT 지오비전 "장소 혼잡도"는 페이지가 동적 렌더링이라 WebFetch로 본문(가격/자격/API 형태)을
