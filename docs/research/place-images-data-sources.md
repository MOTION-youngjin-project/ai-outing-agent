# 장소 사진(이미지) 데이터 소스 조사

조사일: 2026-09-08
조사 목적: 마이페이지 "저장한 장소" 목록 등에 쓸 **실제 장소 사진**을 어디서 가져올 수 있는지 확인. 평점/리뷰/분위기는 `place-reviews-and-mood-data-sources.md`에서 이미 조사 완료(재조사 안 함) — 그 문서에서 유일하게 이미지 필드(`detailImages`)가 있다고 나온 TourAPI(한국관광공사)를 1차 출처로 재검증하고, 다른 대안도 찾았다.

현재 DB 상태: `PlaceImage` 테이블은 스키마만 있고 실제로 채우는 파이프라인이 없어 0건(로컬 확인).

## 1. 한국관광공사 TourAPI — 신청 방법 (1차 출처로 재검증 완료)

**공공데이터포털에서 검색할 정확한 이름**: `한국관광공사_국문 관광정보 서비스_GW`
**제공기관**: 한국관광공사 (관리부서: 디지털인프라팀)
**페이지**: https://www.data.go.kr/data/15101578/openapi.do — WebFetch로 직접 열어 확인, 기존 문서가 링크한 URL이 지금도 유효하고 정확한 상품명임을 재확인함.

이 상세페이지(1차 출처, verbatim 확인)에 명시된 내용:
- **비용**: 무료, 이용허락범위 제한 없음
- **개발계정 트래픽**: 일 1,000건 / **운영계정**: 활용사례 등록 후 신청하면 증량 가능
- **승인절차**: 개발단계 = **자동승인**, 운영단계 = **심의승인**
- **포맷**: REST, JSON+XML
- 설명에 "15종 약 26만 건의 국내 관광 정보"에 **"이미지정보" 항목이 포함**된다고 명시 — 이미지가 있다는 것 자체는 이 공식 상세페이지에 직접 쓰여 있음.
- 단, 이 목록 페이지 자체에는 오퍼레이션별 상세 필드 스키마는 없음(가이드/Swagger로 별도 제공).

**오퍼레이션 이름 실측(이게 기존 문서의 "2018년 아카이브 라이브러리 기준, 미검증" 경고를 푸는 부분)**:
인증키 없이 실제 운영 서버에 요청을 보내 확인함 —
```
curl "https://apis.data.go.kr/B551011/KorService2/detailImage2?serviceKey=test&_type=json&contentId=126000000000000"
→ {"OpenAPI_ServiceResponse":{"cmmMsgHeader":{"errMsg":"SERVICE_KEY_IS_NOT_REGISTERED_ERROR", ...}}}
```
404가 아니라 "서비스키 미등록" 에러가 왔다는 것은 **`KorService2/detailImage2` 오퍼레이션이 지금(2026-09) 실제로 살아있는 현재 버전(TourAPI 4.0, "KorService2" — 예전 "KorService1"의 후속)** 이라는 뜻. 기존 문서가 걱정했던 "옛날 스펙이라 지금도 맞는지 모른다"는 우려는 **해소됨**.

**응답 필드** (보조 출처로 교차확인 — [velog: TourAPI 이미지 조회](https://velog.io/@seongmin0302/api), 구버전 `detailImage1` 기준이라 필드명이 `detailImage2`에도 그대로 이어졌다고 보는 것은 **버전 넘버링 관례상 합리적 추정이나 100% 검증은 아님**):
`contentid`, `originimgurl`(원본), `smallimageurl`(축소), `imgname`, `serialnum`, `cpyrhtDivCd`(저작권 구분)

**콘텐츠 타입 코드** (같은 보조 출처): 12=관광지, 14=문화시설, 15=축제/공연/행사, 25=여행코스, 32=숙박, 38=쇼핑, **39=음식점** — 카페/식당류도 별도 콘텐츠 타입으로 존재하므로 "관광지 아닌 상업시설은 아예 없음"은 아님. 다만 **콘텐츠 타입별로 실제 등록 건수/이미지 보유율 편차가 클 수 있음(미검증 — 실제 신청 후 대구 표본으로 확인 필요)**.

**대구 커버리지**: 별도 확인 못 함(미검증) — 전국 대상 서비스라는 설명은 있으나, 이번 조사에서 실제 키 없이는 대구 표본 조회 불가.

**신청 절차** (상세페이지 기준): "활용신청" 버튼 → 로그인 → 개발계정은 즉시(자동승인) 발급 → 그 키로 개발 단계 호출(일 1,000건) → 서비스 운영 전환 시 "활용사례 등록" 후 심의승인 필요.

### 1-1. 키 발급 후 실호출 검증 (2026-09-08 추가 — 위 "미검증" 경고 해소)

키 발급받은 뒤 대구미술관으로 실제 호출해서 전부 확정함:

- `searchKeyword2`(키워드 검색)로 "대구미술관" 조회 → `contentid=1856967`, 그리고 이 단계에서 이미 대표이미지 필드 **`firstimage`(원본급)/`firstimage2`(축소)**가 바로 내려옴.
- `detailImage2?contentId=1856967`로 갤러리 이미지 조회 → **필드명 확정: `originimgurl`, `smallimageurl`, `imgname`, `contentid`, `serialnum`, `cpyrhtDivCd`** (velog 교차확인이 정확했음이 실측으로 증명됨). 대구미술관 갤러리 이미지 **15장 실존** (`totalCount: 15`).
- 이미지 URL 자체도 실제로 살아있음 확인(`tong.visitkorea.or.kr` 도메인, HTTP 200, 실제 JPG 바이너리 다운로드 성공).
- **주의할 점 하나 발견**: `firstimage`(공식 "대표이미지")로 지정된 사진이 실제로는 미술관 건물이 아니라 **장애인 화장실 접근성 안내 사진**이었음 — 공공데이터가 무조건 잘 큐레이션돼 있다고 가정하면 안 됨. 갤러리(`detailImage2`) 안에는 건물 입구 등 정상적인 사진도 섞여 있으니, `firstimage` 하나만 신뢰하지 말고 갤러리 여러 장 중 사람이 보기에 괜찮은 것을 고르거나, 최소한 "대표사진이 이상할 수 있다"는 전제로 화면을 설계할 것.

## 권장 사항

1. **TourAPI(한국관광공사) 하나로 확정**. 무료이고, 이미지 필드(`originimgurl`/`smallimageurl`/`firstimage`)가 실제로 존재하며 실제 사진까지 다운로드해서 확인 완료(2026-09-08). 이 프로젝트에서 이미지는 이 API로만 받으면 된다.
2. **대구광역시_관광지는 이미지 용도로는 탈락(2026-09-08 실호출로 확정)**. `getTourKorAttractList` 응답에 이미지 URL 필드가 전혀 없음(주소/설명/편의시설/전화 등 텍스트 정보만). 승인이 더 쉽고 쿼터도 넉넉하니 "사진이 아닌" 텍스트 보강용(이용시간, 장애인 편의시설 등 `attr01~05`)으로는 나중에 쓸모 있을 수 있으나, 이번 목적(사진)과는 무관.
3. **문화포털·Kakao·Mapillary·Wikimedia은 이번 프로젝트 용도로는 권장하지 않음** — 문화포털은 대상 자체가 안 맞고(행사 전용), Kakao는 필드가 아예 없고, Mapillary/Wikimedia는 커버리지가 근본적으로 불확실하고 검증 비용(대구 표본을 일일이 확인) 대비 얻는 게 적다.
4. **대표이미지를 곧이곧대로 쓰지 말 것**: `firstimage`가 화장실 안내 사진처럼 부적절한 경우를 실측으로 확인함 — 저장 장소 카드에 쓸 때는 갤러리(`detailImage2`) 여러 장 중 고르거나, 최소한 이상한 사진이 나올 수 있다는 걸 감안한 폴백(예: 사람이 봐도 이상하면 아이콘으로 대체)을 고려할 것.
5. **카페 등 일반 상업시설**: TourAPI 콘텐츠 타입 39(음식점)가 존재하므로 아예 데이터가 없는 카테고리는 아니지만, 실제 등록 밀도는 대구 표본으로 더 확인 필요 — 사진이 없는 저장 장소는 지금처럼 아이콘 placeholder로 두는 최소한의 폴백을 코드에 유지해야 한다(모든 장소에 사진이 있다고 가정하면 안 됨).
